---
name: "Что нового" changelog is fragment-driven
description: Why the web "What's New" section doesn't auto-update from commits/tasks
---

The web cabinet's «Что нового» reads `web/changelog.py` (`CURRENT_VERSION` + `ENTRIES`),
loaded once into Jinja globals at app start (`web/app.py`).

`web/changelog.py` is regenerated by `scripts/build_changelog.py`, which runs as **step 0
of `deploy.sh`**. But it only builds from manually-authored fragment files in
`web/changelog.d/*.md` (one news line per bullet, owner-perspective). Empty folder →
"фрагментов нет — no-op" and the news stays frozen.

**Why it appears "not automatic":** nothing converts merged tasks/commits into fragments.
Parallel task agents ship features but never drop fragments, so the changelog never moves
unless a human/agent writes `web/changelog.d/<slug>.md` before deploying.

**How to apply:** when shipping user-facing features, create `web/changelog.d/<slug>.md`
(unique name avoids merge conflicts), then deploy — build_changelog folds them into a new
minor version, bumps CURRENT_VERSION, optionally AI-polishes (no LLM key → raw lines), and
deletes the fragments. Verify with `python3 scripts/build_changelog.py --dry-run --no-ai`.
Never hand-edit `web/changelog.py` (it gets overwritten). Restart workflow to see new
version locally (loaded at app create time).
