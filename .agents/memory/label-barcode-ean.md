# Ценник: выбор формата штрих-кода

Штрих-код товара (`products.barcode`) рендерится на ценнике и на экране, и в PDF.
Формат выбирается по значению, симметрично на обоих слоях:
- 12 цифр → EAN-13 (контрольная цифра досчитывается)
- 13 цифр → EAN-13 **только если контрольная цифра валидна**, иначе Code-128
- 7 цифр → EAN-8 (досчитывается)
- 8 цифр → EAN-8 **только если валидна**, иначе Code-128
- всё остальное → Code-128

**Why:** `python-barcode` для `ean13`/`ean8` НЕ падает на неверной контрольной цифре —
он молча пересчитывает её и печатает «исправленный» код. Без явной проверки checksum
бэкенд печатал бы один код, а сканер/фронт ожидали другой. JsBarcode на фронте при
невалидном коде вообще ничего не рисует. Поэтому контрольную цифру проверяем сами
ДО выбора формата (а не полагаемся на исключение библиотеки).

**How to apply:** алгоритм checksum унифицирован для EAN-13 и EAN-8 — веса 3,1
чередуются от ПРАВОГО края тела кода (до контрольной цифры), check=(10−sum%10)%10.
Та же математика продублирована в JS (`eanOk`/`pickFmt` в label.html) и Python
(`_ean_checksum_ok`/`_barcode_format` в web/routes/products.py). При изменении одного
слоя — синхронизировать второй. Регресс: `test_label_barcode.py`.
Бэкенд `_make_barcode_img` сохраняет try/except fallback на Code-128 как страховку.
