## Осознанно отложено (сложность vs. риск)
- `create_subscription_addon` не идемпотентен (blind INSERT) — требует деdup по payment_id; риск реален при двойном клике; отложено до специализированного билинг-рефакторинга
- Расхождение путей подтверждения оплаты (бот vs. веб) — бот делает дополнительные обновления org-плана вне `confirm_payment_request`; отложено
- JWT содержит путь к org_db файлу — known risk, смена потребует инвалидации всех сессий; отложено
- `pickle_storage.py` — мёртвый код (main.py не импортирует), но есть в `test_imports.py`; удаление безопасно, но не приоритетно

## Что проверять при будущих изменениях
- Новый web POST, создающий ресурс → обязательно `check_*_limit()` + `if not verify_csrf_token(...)`
- Новый API endpoint → `_api_csrf_ok()` или `X-Requested-With` header в fetch
- Новый метод агрегации данных → SQL GROUP BY/JOIN, не Python-цикл по всем строкам
- Новый индекс → добавлять в `create_tables()` через `CREATE INDEX IF NOT EXISTS`
