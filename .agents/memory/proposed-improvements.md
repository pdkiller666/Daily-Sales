## 🔴 Критично / Безопасность

1. **CSRF в admin.py** — 8 POST-роутов вызывают `verify_csrf_token()`, но игнорируют return value. Нужно добавить `if not verify_csrf_token(...): raise HTTPException(403)`.
2. **Промокоды через `random`** — нужно заменить на `secrets.token_urlsafe()`. Текущие коды предсказуемы при переборе.
3. **TOCTOU в `add_sale`** — проверка остатков и их списание не атомарны. При двух одновременных продажах можно уйти в минус. Нужен `BEGIN IMMEDIATE` или `SELECT ... FOR UPDATE` (SQLite: `BEGIN EXCLUSIVE`).

## 🟡 Продуктовые улучшения

4. **Сравнение периодов на дашборде** — добавить стрелку и «±X% к прошлому периоду» рядом с текущими метриками. Данные в БД уже есть.
5. **ABC-анализ товаров** — на странице продуктов автоматически делить на группы A (80% выручки) / B / C. Помогает фокусировать закупки.
6. **Тренд + мини-прогноз** — мини-график тренда за 30 дней на дашборде (Chart.js уже есть); линейный прогноз на неделю.
7. **Bulk-операции с товарами** — mass-select + batch action: изменить категорию/цену/архивировать нескольким товарам сразу.
8. **Оповещение о входе на сайт** — при логине с нового IP уведомлять пользователя в Telegram (инфраструктура бота уже есть).

## 🟢 UX / Качество жизни

9. **Контекст экспорта виден до скачивания** — показывать «экспортирует: период X, магазин Y» прямо над кнопкой скачивания.
10. **Inline-редактирование цен** — двойной клик по цене в таблице товаров → `contenteditable` / HTMX `hx-trigger="dblclick"`. Без перехода на отдельную страницу.
11. **История изменений товара** — таблица `product_history` + страница `/products/{id}/history`. Лог: кто, когда, что менял (цена/остаток/описание).
12. **Горячие клавиши POS** — цифры 1-9 → быстрый выбор кол-ва, `Enter` → подтверждение. Чисто JS.

## ⚙️ Инфраструктура

13. **Smoke-тесты критических путей** — расширить `test_imports.py`: создание продажи, расчёт зарплаты, генерация Excel без реального Telegram. Защита от регрессий.
14. **Кэширование рейтингов и дашборда** — in-memory TTL 60 с снизит нагрузку при росте данных (паттерн уже есть в `_api_rate_ok`).
