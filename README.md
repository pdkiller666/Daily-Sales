# Daily Sales — Telegram Bot для управления продажами

Профессиональный мультитенантный Telegram-бот для комплексного управления магазинами, продажами, персоналом и подписками. Поддерживает несколько организаций с полной изоляцией данных каждой.

---

## 🚀 Возможности

### 🏢 Мультиарендность (Multi-tenancy)
- Несколько организаций — каждая со своей изолированной SQLite базой данных
- Система ролей: **Директор (owner)** → **Администратор (admin)** → **Сотрудник (user)**
- Зоны доступа для admin: по магазину / городу / торговой сети (мульти-выбор JSON)
- Кастомные названия должностей (`custom_title`)
- **Гибкая оргструктура** (платный модуль `org_structure`, 349₽): подразделения/регионы с иерархией, кастомные роли с набором прав, гранулярный доступ к модулям per-сотрудник; для бесплатного тарифа — минимум (≤3 отдела без иерархии, без кастомных ролей). Кастомная роль раскладывается в стандартные поля — весь старый authz работает без изменений
- **Инвайт-коды** с расширенными возможностями:
  - 🔗 **Deep-link** — ссылка `t.me/bot?start=CODE` → автоматический вход без ввода кода вручную
  - 🔄 **Ротация кода** — кнопка «🔄 Сбросить код» для генерации нового
  - ⚙️ **Пресет роли и магазина** — администратор задаёт роль/магазин при генерации инвайта; при вступлении новый участник пропускает соответствующие шаги регистрации
  - 👤 **Имя из Telegram** — при вступлении предлагается использовать имя из профиля одной кнопкой
  - 🔔 **Уведомление о вступлении** — owner/admin организации получает push-уведомление при каждом новом участнике
- Суперадмин (env_manager) с переключением контекста между организациями

### 💰 Продажи и инвентарь
- Быстрая регистрация продаж (одиночная и мультикорзина)
- **Двухуровневый каталог**: сначала категории (с кол-вом товаров), затем товары внутри
- Сортировка товаров: по названию / цене ↑ / цене ↓; поиск по названию внутри категории
- Быстрый поиск «🔍 Найти товар» по всем категориям среди товаров с ненулевым остатком
- Кнопки количества [1, 2, 3, 5, 10, 20, 50] — без ручного ввода
- Импорт товаров из Excel (📊 Импорт из Excel)
- Пакетный импорт: «Название;Категория;Цена» — до 100 товаров за раз
- Избранные товары (⭐ Избранное) и недавние (🔄 Недавние) с поиском внутри
- Быстрое подтверждение (⚡ Продать сейчас) при первом товаре в корзине
- Складской учёт с историей изменений
- **Редактирование и удаление продаж** с корректировкой остатков (по одной или за период)
- **Массовое удаление продаж** за период по магазину с восстановлением остатков
- **Кросс-продажи**: сотрудник торговой сети может оформить продажу/списание из другого магазина сети

- **Каталог товаров** → 🛍 Управление товарами + 📦 Управление остатками
- **Упр. продажами** → ✏️ Редактировать/удалить + 🗑 Удалить за период

- **Команда** → 👥 Сотрудники + 💰 Зарплата и смены

### 📊 Отчёты и аналитика
- Дашборд администратора: смены, продажи, мотивация команды, все планы — Сегодня / Неделя / Месяц
- Дашборд сотрудника: зарплата, планы, конкурсы — с тем же переключателем периода
- Отчёты по периодам: общий / по магазину / по городу (с ручным фильтром)
- «Текущий месяц» — быстрый отчёт сотрудника с 1-го числа по сегодня
- Рейтинги продавцов, магазинов, городов (7 дней / этот месяц / прошлый)
- Позиция пользователя вне топ-10
- Все времена отображаются в часовом поясе пользователя

### 📥 Экспорт в Excel
- Экспорт из любого раздела отчётов (до 50 000 строк)
- **4 листа**: «Детальный отчёт» (с продавцом, ИТОГО), «По категориям», «По продавцам», «По дням» (с графиками)
- Scope-фильтр при экспорте учитывает зону доступа администратора
- Транслитерированные имена файлов

### 🎯 Планы продаж
- Планы для продавца или магазина
- Периоды: неделя / месяц
- Метрики: оборот (₽) / количество (шт)
- Фильтр по категории или конкретному товару (мульти-выбор)
- Редактирование всех параметров плана
- Уведомления о достижении 50% / 75% / 100% — однократно за период
- Прогресс-бары в дашборде и «Моих планах»
- Поиск магазина / сотрудника / категории / товара при создании плана

### 📅 Зарплата и графики работы
- Ставки сотрудников (daily_rate)
- Календарь смен с отметкой рабочих дней
- Время начала и конца смены для каждого дня
- **Шаблоны смен**: типовое расписание по дням недели (Пн–Вс), автоматически применяется при добавлении смены
- Сотрудник видит своё расписание и времена смен в «Мой профиль»
- Зарплатный итог за месяц

### 💼 Мотивация и комиссии
- Матрица мотивации: ставки комиссии по товарам / категориям / магазинам
- **Помесячное расписание мотивации**: разные ставки на каждый месяц, архив
- Дополнительные условия (бонусы при выполнении KPI)
- **Совместный режим**: пул продавцов делит общий бонус поровну
- Индивидуальные пороги по магазинам в конкурсах

- Фильтры по товарам / категориям / городам / пользователям

### 🌐 Веб-кабинет (FastAPI)

- **URL:** порт 5000, работает параллельно с ботом
- **Аутентификация:** вход через Telegram Login Widget **или по email и паролю** (регистрация по инвайт-коду + подтверждение email)
- **Публичный лендинг** (`/`): промо-страница для посетителей из интернета; если пользователь авторизован — редирект на `/dashboard`
- **Разделы:** Дашборд, Продажи, Товары (CRUD), Инвентарь, Отчёты, Рейтинги, Персонал, Планы, Зарплата, Расписание, Конкурсы, Настройки, Google Sheets, Платежи, **Чат**, **Оргструктура** (owner / super_admin)

- **Корпоративный чат:** тематические каналы (topics) + прямые сообщения (DM) между сотрудниками; WebSocket для мгновенной доставки; поиск по теме и по всем DM одновременно; файловые вложения
- **CRUD товаров:** создание, редактирование, удаление прямо из веб-кабинета
- **Рейтинги:** мгновенный поиск по имени без перезагрузки страницы (Alpine.js)
- **Безопасность:** CSRF-токены на всех POST-формах, JWT 7 дней, stateless HMAC nonce, PBKDF2-SHA256 (390 000 итераций) для паролей, persistent rate limiting (SQLite-backed, выдерживает рестарты)
- **Кликабельные уведомления:** push-уведомления в sidebar навигируют на нужный раздел при клике
- **FAB кнопка чата:** floating bubble на мобильных; badge = непрочитанные сообщения в топиках + непрочитанные DM

## 🏗 Архитектура

- **Multi-tenancy**: каждая организация — изолированная SQLite БД (`data/tenants/org_*.db`)
- **AsyncDatabase wrapper**: `get_db()` возвращает `AsyncDatabase` — методы обёрнуты в `asyncio.to_thread`; thread-local connection pool переиспользует соединения внутри потока
- **Anchor message pattern**: все FSM-флоу редактируют одно сообщение через `fsm_edit()`; `clear_state_keep_org()` всегда ПОСЛЕ `fsm_edit()`, никогда до
- **Hub-навигация**: разделы сгруппированы по логике — 1 кнопка раскрывает хаб с 2–4 подразделами
- **Гибкая оргструктура**: кастомная роль (`org_roles`) раскладывается в стандартные поля `user_org_mapping` (`role`+scope+`custom_title`+`org_role_id`) → старый authz не меняется; `user_module_access` (allow/deny) — override поверх биллинга в `nav_modules`; гейт `org_structure_level()` смотрит биллинг ВЛАДЕЛЬЦА; scope сети = `network`
- **Invite-система**: deep-link (`/start CODE`), ротация кода, пресет роли/магазина, имя из Telegram, уведомление owner/admin
- **APScheduler**: 10 фоновых задач; еженедельная очистка устаревших FSM-записей (`cleanup_fsm_storage`)
- **Persistent rate limiting**: `web/rate_store.py` — SQLite-backed счётчики запросов; выдерживает рестарты; auth-эндпоинты защищены даже после падения процесса
- **Stateless HMAC nonce**: `/auth/code` использует HMAC-SHA256 временной метки вместо хранения состояния в БД
- **Timezone-aware**: все времена хранятся как UTC, отображаются в TZ пользователя
- **Filter system**: scope роли — потолок, ручной фильтр — пол; FSM key `admin_filter` сохраняется при `clear_state_keep_org()`
- **Migrations on access**: `create_tables()` кешируется в `_INITIALIZED_DBS` — выполняется один раз на путь БД за жизнь процесса, повторные вызовы — мгновенный return
- **Hosting**: Amvera (production, persistent mount `/app/data`), Replit (development)
- **Payments**: pluggable провайдеры (СБП / ЮKassa) через `payment_provider.py`
- **Email + пароль аутентификация**: `/register` по инвайт-коду + email + пароль; подтверждение через Яндекс SMTP; сброс пароля через письмо; PBKDF2-SHA256 хеширование; для пользователей без Telegram — synthetic telegram_id в `web_credentials`
